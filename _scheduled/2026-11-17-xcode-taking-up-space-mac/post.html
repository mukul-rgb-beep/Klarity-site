Xcode Taking Up Space on Your Mac? What Is Safe to Clear

DerivedData, device support files, simulators, runtimes and archives: what each one is, which rebuild themselves, which to keep, and how to clear the rest without Terminal.

Xcode’s real size is not in Applications

Look at Xcode in your Applications folder and it seems reasonable: on my Mac, Xcode 27.1 takes under 4 GB. That number hides most of the cost. Everything Xcode makes while you work, the build output, the simulators, the files it copies off your iPhone, lives somewhere else, mostly in a folder macOS hides from you: Developer, inside the Library folder in your home folder.

Storage settings will not tell you much about it. It shows one number, often folded into the grey System Data bar, with no breakdown and no dates. So the space grows quietly, project by project and iOS version by iOS version, until the disk is full and you cannot see why.

When I measured my own Mac for this post, the total was startling. The device support folder held 63 GB, the simulators 49 GB, build output another 7 GB, and the simulator runtimes, which live in a system folder of their own, 34 GB. More than 150 GB in all, about forty times the size of Xcode itself. Most of it can go. The trick is seeing which parts.

What each folder is, and whether it comes back

DerivedData: build output

Every project you build in Xcode gets a folder here, with the compiled app, the index Xcode uses for code completion and search, and logs. Old projects, renamed projects and copies of projects each leave their own folder behind. Safe to clear, and it rebuilds itself. Quit Xcode first. The next build of each project starts from scratch, so it is slower once, and Xcode re-indexes while you wait.

iOS DeviceSupport: files copied from your devices

The first time you connect an iPhone or iPad running an iOS version Xcode has not seen, it copies debugging information off the device. That is the “preparing device” wait. Each iOS version gets a folder of several gigabytes, and they pile up: on my Mac, eight folders, most from iOS 27 beta builds my devices have long since moved past, two of them 13 GB each. There is a watchOS DeviceSupport folder beside it that works the same way. Safe to clear for versions you no longer run. If you connect a device on that version again, Xcode simply copies the files again.

Simulators: one folder per simulated device

Each simulated iPhone, iPad or Watch you have created, or that Xcode created for you, keeps its own storage: the apps you installed on it, their data, photos you dragged in. They live under CoreSimulator, in a folder called Devices, with long random names that tell you nothing. I had 43 of them taking 49 GB. Safe to remove the ones you do not use, but do it from Xcode (below) so its list of simulators stays right. A removed simulator does not come back by itself; you can always create a fresh one.

Archives: the builds you shipped

Every time you choose Product → Archive, Xcode keeps the result in a folder named after the date. These do not rebuild themselves, and this is the one folder to be careful with: an archive holds the debug symbols that turn a crash report into readable function names. Keep the archive for every version still in your users’ hands. Archives for versions nobody runs any more, test builds and abandoned experiments can go.

Simulator runtimes: not in your Library at all

A runtime is the copy of iOS, watchOS or another platform that the simulators run on, and each one is several gigabytes. Here is the part many guides get wrong (our own System Data guide did too, until we corrected it): on current versions of Xcode and macOS, runtimes are not kept in your Library’s Developer folder. macOS stores them in a protected system location, outside your home folder, and Xcode attaches them like disks while you use them. One copy is shared by every version of Xcode on your Mac. On mine, iOS and watchOS runtimes take 34 GB there.

So a scan of your Library will not show them, and you cannot remove them by moving files. Klarity will not move anything inside the System folder to the Trash, and macOS would not let it anyway. Remove runtimes from Xcode’s own settings, as below. Developers on Apple’s forums report the occasional orphaned runtime that Xcode no longer lists and that cannot be deleted by hand; if that happens to you, report it to Apple rather than fighting the system.

Old copies of Xcode

A beta of Xcode kept next to the release, or an old version kept for one project, is several gigabytes each. Move the ones you no longer need to the Trash from Finder. Because runtimes are shared, removing an old Xcode does not remove its runtimes; check Components afterwards (below).

How to clear them from Xcode itself

Xcode has its own controls for most of this, and they are the safest route because Xcode keeps its records straight:

  • Simulator runtimes. Open Xcode → Settings → Components (older versions of Xcode call this tab Platforms). Each installed runtime is listed with its size. Delete the ones you no longer test against; you can download one again from the same place if you need it.
  • Simulators. Choose Window → Devices and Simulators, then the Simulators tab. Control-click a simulator you do not use and choose Delete.
  • Archives. Choose Window → Organizer, then Archives. Each app’s archives are listed by version and date. Delete the old ones you no longer need, keeping those for shipped versions people still use.
  • DerivedData. Product → Clean Build Folder clears only the project you have open. To clear everything, open Xcode → Settings → Locations and click the small arrow next to the Derived Data path; it opens the folder in Finder. Quit Xcode, then move the folders inside to the Trash.
  • Device support files. Xcode has no button for these. Clear them with Finder or Klarity, as below.

Or clear them straight from the map

For DerivedData, device support folders and old archives, Klarity is quicker, because you are already looking at the sizes and the ages. Right-click a rectangle, or use the Move to Trash… button in the inspector.

Klarity treats folders differently depending on where they are, and it is worth knowing how. Most of your Library is app data that apps need, so Klarity shows an extra warning before moving anything from it. Developer is an exception, along with Caches and Logs: clearing them is routine, so anything inside goes straight to the normal confirmation. Folders of 1 GB or more, which most of these are, need a deliberate slide to confirm, so a stray click cannot clear 13 GB.

Klarity only ever moves things to the Trash. It never deletes anything outright and never empties the Trash for you, so a mistake can be put back right up until you empty it. And until you do empty it, the space is not free. Klarity rescans by itself after each move, so you see the rectangle disappear from the map.

What to keep

  • Archives for every version still in use. If you ship an app, someone out there is still on an old version, and its crash reports need that archive’s symbols.
  • The device support folder for the iOS version your phone runs now. Delete it and you just wait through “preparing device” again next time you plug in.
  • Simulators you actually test on, especially ones you have set up with test data.
  • Everything else in Library you cannot name. The rule from how to clean up Mac storage holds here: if you cannot say what made a folder, leave it.

Xcode’s leftovers come back as you keep working, so this is not a one-off. A look at the Developer folder every few months, with age colouring on, keeps it from creeping back to a hundred gigabytes. If you want to go after old files elsewhere too, finding old files on a Mac uses the same red-is-old approach.

Questions people ask

Is it safe to delete Xcode DerivedData?

Yes. DerivedData is build output and indexes, and Xcode rebuilds it the next time you build each project. Quit Xcode first, and expect the first build afterwards to be slower while Xcode re-indexes.

Can I delete the iOS DeviceSupport folders?

Yes, for iOS versions your devices no longer run. Each folder holds debugging files Xcode copied from a device. If you connect a device on that version again, Xcode copies them again. Keep the folder for the version your phone runs now to avoid the wait.

Where are Xcode simulator runtimes stored?

On current versions of Xcode and macOS, runtimes are kept in a protected system location, not in the Developer folder in your Library, and one copy is shared by every installed Xcode. Remove them in Xcode, Settings, Components, not by deleting files.

Should I delete old Xcode archives?

Only for versions nobody uses any more. An archive holds the debug symbols that make crash reports readable, so keep the archive for every version of your app still in people’s hands. Test builds and abandoned experiments can go.
